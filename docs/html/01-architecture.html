1️⃣ agents/ — 编排层

claim_agent.py：LangGraph 状态机核心

核心函数 build_claim_graph(services) 构建主审核图。节点：intake → policy → experts → (auto | investigate | review) → END；专家子图 expert --Send并行--> aggregate；另有规划执行图 planner → execute。两个 interrupt() 中断点：

  • 补材料中断：{kind: 'information', missing: ['policy_id'], round: n+1} — 缺保单号时暂停等待补充；
  • 人工审核中断：{kind: 'review', reason: '需要人工核实证据或大额审批'} — 低置信/大额/证据不足时挂起。

状态通过 SQLite 检查点持久化（.data/checkpoints.sqlite），重启可恢复。

stateDiagram-v2 [*] --> intake intake --> policy : 材料齐全 intake --> intake : 缺材料 interrupt(information) policy --> experts : 核验成功 policy --> review : 失败/缺配置 interrupt(review) state experts { [*] --> fanout fanout --> 定损 fanout --> 风控 fanout --> 判责 定损 --> aggregate 风控 --> aggregate 判责 --> aggregate aggregate --> [*] } experts --> auto : 高置信·低风险·证据足 experts --> investigate : 风险>0.7 experts --> review : 大额/缺证据/低置信/分歧 auto --> [*] investigate --> [*] review --> [*] : 授权恢复后记录人工意见

risk_agent.py：三专家结构化意见

每个专家（定损/风控/判责）通过本地模型产出结构化 Pydantic 意见（意见、评分、依据），经 langgraph.types.Send 并行分发到同一 expert 节点，再由 aggregate 节点汇总为统一消息集。演示模式下使用明确标注的合成专家结果，不实际调用模型。

confidence.py：置信度评估系统

flowchart TB data["① 输入已核实数据与证据似然"] --> models["② 分类模型：LLM + 规则引擎"] models --> confidence["③ Softmax · 熵 · 贝叶斯 · 多模型融合"] confidence --> calibration["④ 正温度缩放 + ECE 校准评估"] calibration --> evidence{"⑤ 证据完整且非大额？"} evidence -->|否| manual["人工复核"] evidence -->|是| high{"评分 > 0.90？"} high -->|是| suggest["受理建议"] high -->|否| mid{"评分 > 0.70？"} mid -->|是| quick["快速复核"] mid -->|否| low{"评分 > 0.50？"} low -->|是| manual low -->|否| investigate["调查核实"]
综合评分是材料的启发式算法，不等于已校准的赔付概率；低分不自动拒赔。confidence_system.py 是它的公共入口，复用 agents 实现。

3️⃣ adapters/ — 真实与演示双后端

BusinessBackend（真实）

BusinessBackend(adapters={...}) 注册组织内真实协议。保单 HTTP 实现来自培训材料；其余接口没有协议，必须显式注册，不能靠默认成功返回值闭环。通知也需审批。

未配置 → 显式失败 → 转人工

DemoBackend（演示）

仅提供材料中的固定教学案例；claims_agent.py --demo 使用明确标注的合成专家结果，不执行实际模型调用。数据标注 demo: true / source: 合成数据；生产环境自动禁用演示入口。

教学/演示专用

4️⃣ models/ · prompts/

  • models/schemas.py：Pydantic 契约（ClaimRequest/ClaimResponse 等）与 Schema 迁移；models/parsers.py：有限修复（如剥 ```json 围栏）；models/workbench.py：工作台对话模型。
  • prompts/review_prompt.py / risk_prompt.py：四场景模板、动态规则注入与本地固定版本，保证可复现。

5️⃣ isolated_deep/ — 独立 Deep Agents 环境

官方 Deep Agents 单独安装于独立依赖环境，配 LangFuse v3 追踪；agents/deep_claims_agent.py 为延迟入口。与主项目（LangFuse v2）隔离，避免依赖冲突，详见 isolated_deep/README.md。LangSmith 演示已移除，自动追踪关闭（langsmith 包仍是 LangChain 0.3 强制传递依赖）。
