💬 上下文继承：省略主语的追问（如「那金额是多少」）继承当前主题；明确的新问题允许切换主题。所以对话不必每次重复案情。

🎬 剧本 A：最短路径走完整链路（材料齐全）

前提：服务已启动，浏览器打开 http://127.0.0.1:8001/。

  1. 点击页面上的 「载入演示」 按钮 —— 注入材料齐全的合成案件（停车场刮擦，保单 POL-2024-001，金额 1286.40）。
  2. 观察页面渲染的完整状态机：报案受理 → 单证核查 → 保单核验 → 三专家并行 → 置信度融合 → 决策建议。
  3. 查看决策链路与每个节点的 trace（模型输入、耗时、输出）。

该入口不调用真实业务系统，生产环境自动禁用。

逐轮对话示例（可直接照抄体验）

# 第 1 轮 —— 故意不带保单号，触发补材料中断
你：我的车昨天在小区停车场被刮蹭了，右后门划痕约30厘米，想申请理赔。

系统：识别意图 = 理赔报案（置信度 0.9x）
      材料审核：❌ 缺少 ①保单信息 ②事故/出险证明 ③费用/损失凭证
      请补充上述材料（第 1/3 轮）

# 第 2 轮 —— 追问继承主题，补充部分材料（上传保单照片 + 现场照片）
你：（附件：保单.jpg、现场照片.jpg）保单和现场照片传上来了

系统：识别意图 = 补充材料
      材料审核：✅保单信息 ✅事故证明 ❌费用/损失凭证
      保留已收附件，请补充维修发票或定损单（第 2/3 轮）

# 第 3 轮 —— 补齐最后一类
你：（附件：维修发票.pdf）发票在这里

系统：材料齐全 ✅ 轮次清零 → 进入理赔链路
      intake → policy（核验 POL-2024-001）→ 三专家并行 → 置信度融合
      → 决策建议（正常：受理；高风险：挂起人工审核）
      页面展示决策链路 + 每节点 trace

⚡ SSE 流式问答事件流

POST /api/assistant/stream 逐段推送（data: {...}\n\n），工作台实时渲染：

data: {"intent": "理赔报案", "intent_confidence": 0.93}      ← 意图识别完成
data: {"trace": {"stage": "intent", "status": "running", ...}}  ← 节点 trace
data: {"trace": {"stage": "material", "status": "done", "missing": [...]}}
data: {"delta": "根据您提供的材料..."}                            ← 流式正文片段
data: {"done": true}                                             ← 结束

trace 包含节点名、状态、模型名、耗时、输入输出摘要；附件仅在请求内存中处理，不落盘。

🔌 curl 等价走法（API 直连全链路）

# 1) 创建审核工作流 —— 缺保单号 → 补材料中断
curl -X POST http://127.0.0.1:8001/api/claims/process \
  -H "Content-Type: application/json" \
  -d '{"claim_id":"CLM-TEST-001","description":"测试：缺少保单号的报案"}'

# 2) 补齐保单号 —— 仅补材料阶段接受 policy_id
curl -X POST http://127.0.0.1:8001/api/claims/CLM-TEST-001/supplement \
  -H "Content-Type: application/json" \
  -d '{"policy_id":"POL-2024-001"}'

# 3) 高风险案件挂起后，审核员恢复（Key 在 .env 的 REVIEWER_API_KEY）
curl -X POST http://127.0.0.1:8001/api/claims/CLM-TEST-001/review \
  -H "X-Reviewer-Key: <REVIEWER_API_KEY>"

# 4) 随时查询已持久化案件状态
curl http://127.0.0.1:8001/api/claims/CLM-TEST-001

# 5) 纯对话流式问答（结合案件与单证上下文）
curl -X POST http://127.0.0.1:8001/api/assistant/stream \
  -H "Content-Type: application/json" \
  -d '{"message":"我的案件审核到哪一步了？"}'
请求返回的是审核建议，不执行支付；拒赔需授权人工提供条款依据；低置信/证据不足/大额自动转人工。
