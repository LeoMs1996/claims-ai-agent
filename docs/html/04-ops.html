🛣️ API 路由全解

路由方法行为
/healthGET仅进程存活，不代表模型可用
/api/claims/processPOST创建审核工作流；缺保单号进入补材料中断（支持 description/claim_text + 可选 policy_id/amount）
/api/demo/claims/processPOST固定合成案件跑完整状态机；仅非生产环境
/api/claims/{claim_id}GET查询已持久化案件状态
/api/claims/{claim_id}/supplementPOST仅补材料阶段接受 policy_id
/api/claims/{claim_id}/reviewPOSTX-Reviewer-Key 认证后恢复人工审核
/metricsGETPrometheus 格式指标（六组业务指标）
/docsGET自动生成的交互式 API 文档（Try it out）
/GET理赔智能工作台（对话 UI）
/api/documents/analyzePOST内存解析并识别最多 6 份理赔单证
/api/assistant/streamPOST结合案件和单证上下文的流式问答（SSE）
生产必须配置 CLAIMS_API_KEY 和 REVIEWER_API_KEY；示例不支持多租户行级权限，也不能直接横向扩容。SQLite 检查点在 .data/checkpoints.sqlite，重启可恢复。

📦 安装与本地启动

# Python 3.10 兼容；推荐干净的 3.12 venv
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check

# 首次创建；已有 .env 不要覆盖
if [ ! -f .env ]; then cp .env.example .env; chmod 600 .env; fi

# 离线验证
python -m pytest -q
python claims_agent.py --demo
python -m demos.module04_demo --prompts
python -m scripts.benchmark_parsers

# 启动 HTTP 服务
uvicorn app:app --host 127.0.0.1 --port 8001
curl -fsS http://127.0.0.1:8001/health
python health_check.py   # 三条健康与状态机验证

# 或一键验证
bash scripts/verify.sh

🔒 安全边界与生产要求

密钥与鉴权

  • settings.py Pydantic 校验环境密钥；.env.example 不含真实密钥
  • 生产必配 CLAIMS_API_KEY（业务）与 REVIEWER_API_KEY（人工审核恢复）
  • 附件仅内存处理不落盘；中间件脱敏 PII 后才进审计/追踪

诚实性原则

  • 真实模式未配置业务适配器 → 转人工，不返回假保单/虚构定损
  • 流式服务不返回 usage 时用量标「未知」，不声称零成本
  • CI 自动部署默认关闭：需生产审批、SSH 信任、固定镜像与目标检出版本

⚠️ 已知边界（务必阅读）

  • 离线演示不代表真实模型、赔付系统或向量服务已联通。
  • 对话页「真实模式」（LLM 问答、图片识别）需 .env 中 bailian/GLM 凭证可用；纯理赔状态机演示不受影响。

  • 示例不支持多租户行级权限、不能直接横向扩容。
  • 固定 seed 只尽力复现，不保证完全一致。
