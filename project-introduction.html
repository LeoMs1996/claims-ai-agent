🛡️ claims-ai-agent · 理赔智能体项目

基于 LangChain 0.3 + LangGraph 的保险理赔审核智能体系统：多轮对话工作台、三专家并行风险分析、置信度评估、人机协同（HITL）审批、RAG 检索与全链路可观测，实现从报案到决策的完整理赔状态机。

Python 3.10+ FastAPI LangGraph 状态机 Milvus 混合检索 Redis 记忆 LangFuse 追踪 Prometheus 监控 Docker 部署

一、项目概览

本项目是依据 claims-langchain-training.md 培训材料实现的分层理赔 Agent 系统，覆盖代码、演示、测试与部署配置。其核心原则是诚实的工程边界：

  • 真实模式下未配置业务适配器会转人工处理，绝不返回假保单或虚构定损结果；
  • 拒赔必须由授权人工提供条款依据；低置信度、证据不足或大额案件一律转人工；
  • 本地推理为默认模式，云端（GLM / 百炼）需显式选择切换；
  • 离线演示明确标注为合成数据，不代表真实模型或赔付系统已联通。

二、核心架构与理赔链路

端到端审核流程

📝 报案受理描述 / 理赔文本
→
🔍 保单查询policy_tool 核验
→
📥 补材料缺失自动中断追问
→
👥 三专家并行Send 消息分发
→
🎲 置信度融合校准 + ECE
→
✅ 决策 / 转人工HITL 审批
⚠️ 人机协同边界：低置信度、证据不足、大额案件自动转人工；写操作（赔付、通知）只有服务端 authorize 核对案件、金额、收款方等参数后才进入幂等 Outbox，且需审批通过。

三、智能工作台（Web UI）功能

启动服务后访问 http://127.0.0.1:8001/ 即可使用「理赔智能工作台」：

  • 多轮对话 —— 分类器读取最近六条消息和上一轮意图：省略主语的追问继承当前主题，明确的新问题允许切换主题；
  • 五类理赔意图识别 —— 进入理赔专用提示词和合规约束，一般咨询交给通用基模回答；
  • 单证智能解析 —— 支持 PDF / DOCX / 文本抽取与图片视觉识别（OpenAI 兼容多模态消息），每次最多解析 6 份理赔单证，附件仅在内存中处理、不落盘；
  • 材料完整性审核 —— 按附件类型核查保单信息、事故/出险证明、费用/损失凭证；缺失时保留累计附件并最多回流追问三轮，仍不完整则建议转人工，材料补齐后轮次清零并继续理赔链路；
  • 流式问答 —— /api/assistant/stream 结合案件上下文和单证识别结果流式输出；
  • 演示模式 —— 点击「载入演示」用固定合成案件运行完整状态机，查看报案、保单、三专家、置信度和决策全链路（不调用真实业务系统，生产环境自动禁用）。

四、HTTP API 一览

路由行为说明
GET /health进程存活检查（不代表模型可用）
POST /api/claims/process创建审核工作流；缺保单号时进入补材料中断
POST /api/demo/claims/process固定合成案件运行完整理赔状态机（仅非生产环境）
GET /api/claims/{claim_id}查询已持久化案件状态（SQLite 检查点，重启可恢复）
POST /api/claims/{claim_id}/supplement补材料阶段接受 policy_id
POST /api/claims/{claim_id}/reviewX-Reviewer-Key 认证后恢复人工审核
POST /api/documents/analyze内存解析并识别最多 6 份理赔单证
POST /api/assistant/stream结合案件与单证上下文的流式问答
GET /metricsPrometheus 格式业务指标
GET /docs / GET /自动接口文档 / 理赔智能工作台
⚠️ 返回的是审核建议，不执行支付。生产环境必须配置 CLAIMS_API_KEY 与 REVIEWER_API_KEY；示例不支持多租户行级权限，也不能直接横向扩容。

五、模型接入：本地推理优先，云端显式切换

模式配置说明
local（默认） LOCAL_LLM_BASE_URL / API_KEY
LOCAL_FAST / MAIN / PRO / VISION_MODEL		 连接本地推理服务（默认端口 8000）；模型名必须与推理服务实际注册名一致。
bailian（云端） MODEL_PROVIDER=bailian
OPENAI_BASE_URL / API_KEY		 默认指向 GLM 的 OpenAI 兼容端点（open.bigmodel.cn），plus/max/flash 三档默认 glm-5.3，vision 档为 glm-4v-plus。

模型服务需支持 OpenAI 兼容的 chat / JSON / tools 能力；部分流式服务不返回 usage，此时用量标记为「未知」，不声称零成本。

六、RAG 检索与记忆系统

📚 RAG 混合检索

  • load_documents 要求险种、版本、生效日期齐全；
  • ClaimVectorStore 基于 Milvus，默认不删除旧集合；
  • 混合检索采用加权 RRF 融合，重排通过已核实的 reranker 函数注入；
  • 带引用校验；扫描版 PDF 需另接 OCR。

🧠 上下文记忆

  • ClaimContextManager 支持窗口记忆、摘要压缩、实体冲突检测；
  • 可注入 Redis 客户端实现持久化；
  • 摘要链与实体抽取器均可插拔；
  • Qwen 模型需注入匹配的 token_counter，默认 cl100k_base 仅作教学计数。

八、快速开始

安装与离线验证

# Python 3.10 兼容（推荐干净环境）
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check

if [ ! -f .env ]; then cp .env.example .env; chmod 600 .env; fi

python -m pytest -q                      # 测试
python claims_agent.py --demo            # 端到端离线演示
python -m demos.module04_demo --prompts  # 提示词演示
python -m scripts.benchmark_parsers      # 解析基准

启动 HTTP 服务

source .venv/bin/activate
uvicorn app:app --host 127.0.0.1 --port 8001

# 另一个终端验证
curl -fsS http://127.0.0.1:8001/health
python health_check.py

基础设施联调（需要 Docker）

docker compose --profile infra up -d --wait etcd minio milvus redis
RUN_MILVUS_TESTS=1 python -m pytest -q tests/test_milvus_integration.py

# 自托管 LangFuse
docker compose -f docker-compose.langfuse.yml up -d

# 上线前门禁
python -m deploy.regression_gate metrics.json --cost-budget 实际预算
✅ 也可运行 bash scripts/verify.sh 一键完成「启动 + pytest」两条验证链路。

九、部署与运维

  • Dockerfile：非 root 用户运行、暴露 8001 端口、单工作进程；
  • docker-compose.yml：应用 + Redis / Milvus（etcd / MinIO）完整基础设施栈；
  • docker-compose.langfuse.yml：独立自托管 LangFuse 追踪平台；
  • deploy.sh：固定镜像版本发布，失败自动回退；
  • CI（GitHub Actions）：检查 → 测试 → 容器集成 → 构建 → 可选发布；自动部署默认关闭，须配置生产审批、SSH 信任与固定镜像后启用；
  • deploy/ 目录：对拍、门禁、环境配置、监控告警与运维手册。
